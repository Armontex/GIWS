## Зачем нужен GIWS?

Обычно GNOME переключает рабочий стол сразу на всех мониторах. GIWS сохраняет
знакомые сочетания клавиш, но учитывает монитор под указателем мыши.

| Действие                    | Что происходит                                            |
| --------------------------- | --------------------------------------------------------- |
| Сочетание на любом мониторе | Рабочий стол меняется со штатной анимацией и popup GNOME. |
| Колесо мыши в Overview      | Меняется только представление под указателем.             |
| Активация через Dash/окно   | Меняется только монитор, где находится выбранное окно.    |
| Остальные мониторы          | Их видимые окна и контекст рабочего стола не меняются.    |

Не нужно осваивать новые сочетания клавиш, отдельный переключатель или другую
модель взаимодействия — продолжайте работать с GNOME привычным способом.

## Как это работает

1. GIWS отслеживает смену рабочих столов из штатных сочетаний и при активации
   окон, включая переходы через Dash и прокрутку в Overview.
2. Для сочетаний целевой монитор определяется по указателю, а для активации —
   по выбранному окну.
3. GNOME выполняет переход, GIWS компенсирует остальные мониторы и оставляет
   штатную визуальную обратную связь только на целевом дисплее.

При отключении расширения исходные обработчики сочетаний GNOME
восстанавливаются.

## Возможности

- **Переключение с учётом монитора** — меняйте рабочий стол там, где работаете.
- **Штатные сочетания клавиш** — настраивайте их в параметрах GNOME как обычно.
- **Штатная обратная связь на каждом мониторе** — анимация GNOME следует за
  целевым дисплеем, а при переключении сочетанием за ним следует и popup.
- **Корректный жизненный цикл** — при отключении GIWS восстанавливает исходные
  обработчики.
- **Кодовая база на TypeScript** — строгие проверки и компиляция в нативные
  ES-модули GJS.
- **Изолированная runtime-проверка** — smoke-тесты запускают GNOME Shell, не
  изменяя активный сеанс рабочего стола.

## Установка

> [!IMPORTANT]
> Сейчас GIWS предназначен для **GNOME Shell 46**, статических рабочих столов и
> конфигурации, в которой рабочие столы охватывают все дисплеи. Перед установкой
> ознакомьтесь со [статусом проекта](#статус-проекта).

### Из CI-артефакта

1. Откройте последний успешный
   [запуск CI для develop](https://github.com/Armontex/GIWS/actions/workflows/ci.yml?query=branch%3Adevelop).
2. Скачайте и распакуйте артефакт `giws-extension`.
3. Установите находящийся внутри `giws@armontex.shell-extension.zip`:

```bash
gnome-extensions install --force giws@armontex.shell-extension.zip
```

При использовании Wayland выйдите из системы и войдите снова после установки
нового расширения. Затем подготовьте GNOME и включите GIWS:

```bash
gsettings set org.gnome.mutter dynamic-workspaces false
gsettings set org.gnome.mutter workspaces-only-on-primary false
gnome-extensions enable giws@armontex
```

Если эти требования к рабочим столам не выполнены, GIWS откажется включаться и
не изменит штатные сочетания клавиш.

### Из исходного кода

Требования:

- Node.js 22.18 или новее и npm 10;
- `zip`, `glib-compile-schemas` и `gnome-extensions`;
- GNOME Shell 46 для установки и runtime-проверки.

```bash
git clone --branch develop https://github.com/Armontex/GIWS.git
cd GIWS
npm ci
npm run install:extension
```

## Использование

Поместите указатель мыши на монитор, которым хотите управлять, и используйте
обычные сочетания GNOME для переключения рабочих столов. Распространённые
варианты:

- `Ctrl+Alt+Left` / `Ctrl+Alt+Right`;
- `Super+Page Up` / `Super+Page Down`.

Конкретные сочетания по-прежнему задаются в параметрах GNOME.

## Статус проекта

GIWS находится в активной разработке. В `develop` находятся последние
интегрированные изменения, а `main` зарезервирована для стабильных выпусков.

Текущая совместимость и ограничения:

| Область                   | Текущая поддержка                       |
| ------------------------- | --------------------------------------- |
| GNOME Shell               | Версия 46                               |
| Режим рабочих столов      | Статические                             |
| Конфигурация дисплеев     | Рабочие столы охватывают каждый дисплей |
| Навигация                 | Влево и вправо                          |
| Окна                      | Обычные окна приложений                 |
| Визуальная обратная связь | Штатная анимация на каждом мониторе     |

Закреплённые, специальные и другие нестандартные окна не затрагиваются. Для
оценки видимой анимации и реакции на клавиатуру всё ещё рекомендуется короткая
ручная проверка на физических мониторах.

## Качество и тестирование

Основная проверка качества включает форматирование, ESLint, TypeScript,
production-сборку и полный набор тестов Vitest:

```bash
npm run check
```

Модульные тесты покрывают независимые от GNOME расчёты рабочих столов,
shell-адаптеры, очистку ресурсов жизненного цикла и контракт сборочного
артефакта.

Linux-only runtime smoke-тест запускает отдельные headless-сеансы GNOME Shell с
изолированными D-Bus, dconf и XDG-каталогами. Он проверяет:

- жизненный цикл расширения: `ACTIVE → INACTIVE → ACTIVE`;
- обнаружение двух виртуальных мониторов;
- обработку штатных сочетаний клавиш через Mutter;
- размещение окон на основном и вторичном мониторах;
- активацию окон в стиле Dash в обоих направлениях;
- переключение колесом мыши и жестами тачпада с учётом монитора;
- выбор целевого монитора для штатной анимации и popup;
- отсутствие runtime-ошибок GJS во время сценария взаимодействия.

```bash
npm run runtime:smoke
```

Smoke-окружение не изменяет активный сеанс рабочего стола.

## Разработка

```bash
npm ci
npm run check
npm run pack
```

| Команда                 | Назначение                                          |
| ----------------------- | --------------------------------------------------- |
| `npm run check`         | Форматирование, lint, типы, сборка и тесты          |
| `npm test`              | Сборка и запуск тестов                              |
| `npm run build`         | Компиляция расширения в `dist/`                     |
| `npm run pack`          | Создание устанавливаемого ZIP-архива                |
| `npm run runtime:smoke` | Изолированная проверка жизненного цикла и поведения |

Коммиты и заголовки pull request следуют стандарту
[Conventional Commits](https://www.conventionalcommits.org/). Ссылки на Jira
намеренно не используются.

### Структура проекта

```text
src/
├── core/          # независимая от GNOME логика рабочих столов
├── lifecycle/     # очистка зарегистрированных runtime-ресурсов
├── logging/       # контекстное журналирование
├── preferences/   # компоненты окна настроек
├── settings/      # типизированный доступ к GSettings
├── shell/         # адаптеры GNOME Shell и Mutter
├── extension.ts   # корень композиции runtime
└── prefs.ts       # корень композиции настроек
```

Runtime-ресурсы должны регистрироваться в disposable stack и освобождаться в
`disable()`.

## Решение проблем

Просмотр логов GNOME Shell:

```bash
journalctl --user -f -o cat /usr/bin/gnome-shell
```

Отключение GIWS из терминала:

```bash
gnome-extensions disable giws@armontex
```

Если сеанс не может загрузить пользовательские расширения, глобально отключите
их из TTY:

```bash
gsettings set org.gnome.shell disable-user-extensions true
```
